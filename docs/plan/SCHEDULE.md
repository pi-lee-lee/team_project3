# 주간 계획서 (2026-11-23 ~ 2027-01-22)

젯봇 · 투척기 · 터틀봇 · 웹을 **처음부터 만든다고 가정**한 9주 계획이다. 5명이 맡고, 마지막 1주는 통합 테스트 기간이다.
무엇을 만드는지는 [SCENARIOS.md](../design/SCENARIOS.md), 서로 주고받는 모양은 [INTERFACES.md](../design/INTERFACES.md) 를 기준으로 한다.

## 1. 전제

| 항목 | 내용 |
| --- | --- |
| 기간 | 2026-11-23(월) ~ 2027-01-22(금), 9주 |
| 인원 | 5명. 이름이 정해지지 않아 담당 파트로 A~E 라고 적었다 — 실제 이름으로 바꿔 쓴다 |
| 파트 | 웹(백엔드 + 화면) · 카메라 · 터틀봇 · 젯봇 · 투척기. 백엔드와 화면은 한 파트로 합쳤고, 카메라(촬영 · 영상 · 판독 · 감지)는 따로 떼어 한 파트로 두었다 |
| 공휴일 | 12-25(금) 성탄절, 01-01(금) 신정 — 5주차 · 6주차는 4일이다 |
| 마지막 주 | 9주차(01-18 ~ 01-22)는 통합 테스트. 새 기능을 만들지 않는다 |
| 개발 방식 | **시뮬레이션에서 먼저 끝까지 돌리고, 실물은 그 뒤에 붙인다.** 실물이 늦어져도 웹과 흐름은 멈추지 않는다 |
| 약속 | 서로 닿는 곳은 토픽 계약과 API 로만 닿는다. 2주차까지 계약을 확정하고, 그 뒤 바꿀 때는 문서를 먼저 고친다 |

이 계획은 지금 저장소의 구현(시뮬레이션에서 동작하는 부분)을 만들며 걸린 일의 크기를 바탕으로 잡았다. 실물 장비 쪽(젯봇 위치 추정, 투척 정확도)은 해 본 적이 없는 일이라 **가장 불확실하다** — 6장의 위험 항목을 본다.

## 2. 역할

| | 파트 | 맡는 것 | 주로 닿는 사람 |
| --- | --- | --- | --- |
| **A** | 웹 (백엔드 + 화면) · 통합 책임 | Docker 스택, gateway · user-service · inspection-service · robot-service, DB, React 화면 전부(사용자 · 관리자 · 관제 대시보드 · 팝업 · 시연), 주간 통합 | 전원 |
| **B** | 카메라 | 카메라 구동과 영상 중계(터틀봇 · 젯봇), 촬영, 스테레오 보정, analysis-service, 판독기(물체 · 계기판 · 표시등 · 열화상), 소화기 인식 모델, 실시간 화재 감지, 조준용 대상 찾기 | A, C, D |
| **C** | 터틀봇 · 시뮬레이션 | ROS 2 시뮬레이션, 지도, Nav2 주행, 목표 브리지, 터틀봇 실기, 주행 제어기 개선 | A, B, E |
| **D** | 젯봇 | ROS 1 → ROS 2 마이그레이션, 구동, 위치 추정(마커 정렬 · 대상 기준 보정), 순찰, 감지 보고 | A, B, C |
| **E** | 투척기 · 시험 | 투척기(아두이노 + SG90) 기구 · 펌웨어 · 시리얼 브리지 · 장착, 사거리 측정, 전 구간 시험과 시연 스크립트 | A, B, C |

- **A 가 통합 책임**이다: 매주 금요일에 그 주의 결과를 한 스택에 올려 함께 돌려 본다.
- **A 는 백엔드와 화면을 함께 맡는다.** 기능 하나를 API 와 화면까지 한 사람이 끝내므로 넘겨주는 시간이 없지만 일이 가장 많다. 그래서 전 구간 시험과 시연 스크립트는 E 가 맡는다.
- **B 는 "카메라로 보는 일" 전부**를 맡는다: 영상이 나오게 하는 것(구동 · 중계 · 보정)부터 그 영상을 읽는 것(판독 · 감지)까지. 로봇을 움직이는 일은 C · D 의 몫이다.
- **D 는 젯봇을 움직이고 위치를 아는 일**에 집중한다. 젯봇의 카메라 영상과 열화상 감지는 B 가 만들어 넘긴다.

## 4. 파트별 계획서

각 표의 "끝났다고 보는 기준"이 그 주 금요일 통합 때 확인하는 것이다.

### A — 웹 (백엔드 + 화면) · 통합 책임

기능 하나를 API 부터 화면까지 한 주에 함께 끝낸다. 표의 "할 일"은 **백엔드 / 화면** 순서로 적었다.

| 주차 | 할 일 | 산출물 | 끝났다고 보는 기준 |
| --- | --- | --- | --- |
| 1 | **백엔드:** Docker Compose 스택(nginx · gateway · 서비스 · DB), 서비스별 DB 와 마이그레이션 틀, user-service 로그인(쿠키 JWT) · 사용자 · 역할 5종 · 초기 계정. **화면:** 화면 설계(구조 · 흐름), React 프로젝트, 공통 부품(목록 · 상세 · 폼), 로그인, 역할별 메뉴 틀 | `compose.yaml`, 서비스 뼈대 4개, 로그인 API, 화면 구조도, 공통 부품 | `docker compose up` 한 번으로 뜨고, 로그인하면 역할에 맞는 화면 틀이 열린다 |
| 2 | **백엔드:** gateway 토큰 검증 · 경로별 역할 정책 · 감사 기록. robot-service 로봇 등록, rosbridge 어댑터(상태 · 목표 보내기 · 영상 중계), 모의 로봇. **토픽 계약과 API 를 문서로 확정**(B · C · D · E 와 함께). **화면:** 관리자 — 사용자 · 로봇 · 점검 지점(지도에서 위치 찍기) · 감사 로그 · 시스템 상태 | 권한 규칙표, 로봇 어댑터, `INTERFACES.md` 확정본, 관리자 화면 | 화면에서 시뮬레이션 로봇을 지점 하나로 보낸다. 관리자가 사용자와 지점을 만들고 고친다. 계약 문서에 전원이 동의 |

| 4 | **백엔드:** 예약 점검(한 번 · 간격 · 매일 · 매주, 로봇이 바쁘면 대기), 사람 판정, 재점검, 지점 이력. **화면:** 관제 지도 모드(로봇 위치 · 경로 · 눌러서 이동), 점검 계획(예약), 관측 상세와 판정, 지점 이력. 스마트폰 · 태블릿 대응 | 예약 · 판정 API, 지도 모드, 계획 · 판정 화면 | 기본 점검 흐름을 화면만으로 끝까지 한다. 전 구간 시험(기본)이 통과한다 |
| 5 | **백엔드:** 규칙 · 판독 결과 저장, 경고(열기 · 확인 · 해제 · 자동 해제), 설정, 대시보드 요약 API, 대시보드 전용 역할. **화면:** 규칙 편집(판독기 설정으로 그리는 폼, 사진으로 규칙 시험), 설정, 경고, **관제 대시보드**(16:9 고정, 다크) | 규칙 · 경고 · 설정 API 와 화면, 대시보드 | 대상을 바꾸고 점검하면 경고가 생기고, 되돌리면 스스로 풀린다. 대시보드 한 화면에 로봇 · 지도 · 경고 · 작업이 보인다 |
| 6 | **백엔드:** 사건 흐름(감지 → 출동 → 재판독 → 승인/자동 투척 → 현장 감시 → 종료), 가로채기, 투척 명령 · 투척 위치 계산, 닫은 뒤 다시 열기, 시연 실행기. **화면:** 사건 목록 · 상세, **비상 팝업**, **투척 승인 팝업**(실시간 카메라 + 승인), 대시보드 사건 패널, 시연 화면 | 사건 API, 투척 명령, 사건 화면, 팝업 2종, 시연 화면 | 화재 시나리오를 화면에서 승인까지 끝낸다. 전 구간 시험(시나리오)이 통과한다 |
| 7 | **백엔드:** 젯봇 연결 — 로봇 종류, 미션 앞뒤 정렬, 감지 보고 받기. 두 로봇의 조정(자리 예약 · 우선순위 · 간격 유지). **화면:** 대시보드와 지도에 젯봇 · 순찰 경로 · 위치 신뢰도, 로봇 종류별 표시 | 젯봇 미션 경로, 조정 로직, 젯봇 표시 | 모의 젯봇과 시뮬레이션 터틀봇이 같은 지도에서 서로 피하고, 화면에 구분되어 보인다 |
| 8 | **백엔드:** 실물 통합 — 실기 로봇 등록 · 설정값 입력, 실물에서 나온 오류 수정. **화면:** 실물로 화면 확인(갱신 주기 조정, 상황실 모니터에서 대시보드), 문구 · 빈 화면 · 오류 안내 다듬기, 사용 안내 문서 | 실물용 설정, 화면 수정, 사용 안내 | 실물 3종이 한 스택에 붙어 시나리오가 한 번 돈다. 실물 영상과 위치가 화면에서 끊기지 않는다 |

## 7. 일하는 방식

- **매주 금요일 통합:** 그 주의 결과를 한 스택에 올려 함께 돌린다. 안 되는 것은 그 자리에서 다음 주 첫 일로 잡는다.
- **계약 먼저:** 다른 사람과 닿는 것(토픽 · API · DB)을 바꿀 때는 문서를 먼저 고치고 알린다.
- **모의 장치로 먼저 통합:** 실물이 없어도 같은 계약에 답하는 모의 장치(모의 로봇 · 모의 투척기 · 감지 보고 도구)로 흐름을 끝까지 돌린다.
- **측정은 표로 남긴다:** 정확도 · 속도 · 오판 비율은 재는 대로 표에 적고, 설정값의 근거로 쓴다.
