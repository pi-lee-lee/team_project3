# 월요일 회의 요약

2026-11-16 회의용 · 개인 희망과 분석자 제안 · 상태 기록은 [08 문서](08_DECISIONS_OPEN_QUESTIONS.md)에서 관리한다.

## 먼저 말할 시나리오

> 화재 위험과 관련해 여러 지점을 반복 확인해야 하는 시설을 생각하고 있다. 관리자가 확인할 지점을 요청하면 로봇이 방문해 사진과 기록을 가져오고, 담당자는 확인 결과나 추가 점검 필요를 남긴다. 모의 이상 신고가 들어오면 해당 지점을 다시 확인하고, 팀원이 제안한 모형 대응 장치도 필요성과 시험 결과에 따라 연결할 수 있다. 자료를 더 조사할 때는 PC 앱으로 내려받아 분석·비교하고 결과를 보존한다. 실습실과 산업 현장 중 어떤 배경이 좋을지는 함께 탐색하고 싶다.

**개인 개발 희망과 검토할 후보를 준비했다. 실제 주제·범위·구조·담당은 팀과 함께 정한다.**

## 장소와 화재를 어떻게 생각하는가?

검토 배경은 **실습실 1개 + 산업 현장 10개**로 정리한다. 실습실도 후보로 유지한다. 산업 후보와 사례는 [09 요약](09_INDUSTRY_MEETING_BRIEF.md)에서 비교한다.

실습실 자체의 퇴실·충전 구역 점검을 개선하는 안과, 실습실에 창고·공장 모형을 꾸미는 안은 사용 목적이 다르다. 실제 사용자의 불편·관측할 대상·이동의 추가 가치를 확인해 배경을 좁힌다.

| 연결할 방향 | 첫 시험에서 보여 줄 성과 |
| --- | --- |
| 예방을 위한 점검 지원 | 표시·외관·통로의 확인 결과와 증거 기록 |
| 이상 징후 관측·재확인 | 모의 경보 또는 관측 요청의 해당 지점 방문·추가 확인 |
| 모의 사고 대응 | 모의 신고·후속 조치 요청·선택한 비위험성 대응 시험 |

경고 표시를 확인한 결과, 실제 발열·화재를 감지한 결과, 모형 장치를 작동한 결과는 각각 기록한다. 실제 화재 감지·소화 효과는 해당 센서와 별도 평가가 필요하다. 구체적인 구분은 [02 PBL 목표](02_PBL_GOALS.md#fire-goals)에 둔다.

## 가장 먼저 지킬 기준

1. **PBL** — 누가 어떤 어려움을 겪으며 어떤 해결 대안을 비교할지 정한다.
2. **단계별 완결성** — 어려운 확장 전에 한 건의 확인·분석 업무를 끝낸다.
3. **개인 희망의 의미 있는 연결** — 웹·독립 PC 앱·실행/통신·기존 로봇 상태·Docker 각각에 실제 역할을 찾는다.
4. **추가 도전** — OpenCV 심화·ML·자동 판정·모형 투척 등은 필요와 시험 결과로 선택한다.

로봇팔과 목 구동은 함께 잠정 폐기 상태다. 저렴한 서보모터를 이용한 투석기형 모형 투척은 별도 후보로 유지한다.

## 내가 개발해 보고 싶은 범위

| 영역 | 희망하는 역할 |
| --- | --- |
| ① 웹·백엔드·DB | 다른 PC의 사용자가 허용된 업무를 요청하고 진행·결과·공식 기록을 확인 |
| ② 독립 PC 앱 | 자료를 일반 폴더로 확보하고 오프라인 반복 분석·외부 도구 활용·결과 보존·선택 제출 |
| ③ 시스템·통신 SW | 실제 로봇 작업·장치 연동·수집·상태 전달·오류 처리·복구 |
| 로봇 상태·Docker | 제공되는 상태값을 판단·조사에 활용하고 서비스 재현·재시작·보존 시험 |

이 범위는 개인의 강한 희망이다. 팀 채택·담당 배정·프로그램 수·실행 위치는 함께 검토한다.

27개 후보는 우선 **원격 업무 / 실행·상태·통신 / PC 자료·분석 / 모형 대응 / 환경·시험**의 다섯 묶음으로 소개한다. 번호별 상세와 연결 관계는 [07 문서](07_FEATURE_CANDIDATES.md#discussion-groups)에서 선택해 읽는다.

## 작은 완료 모습

- **팀 업무**는 한 지점의 요청 → 방문·관측 → 원본·시각·실패 사유 저장 → 사람의 확인 또는 확인 불가 기록까지 연결한다.
- **PC 업무**는 같은 지점의 자료를 로컬 폴더로 가져와 실제 계산 한 종류를 실행하고, 설정·결과를 저장한 뒤 오프라인에서 다시 연다. [반복 점검 자료 분석 예시](04_DESKTOP_APP.md#usage-example)
- 모의 데이터·샘플 파일 시험과 실장비 관측·연동 결과는 각각 표시한다.

## 이번 회의의 목적

| 시점 | 공유·탐색할 내용 |
| --- | --- |
| 이번에 공유 | 각자의 개발 희망, 화재 관련 관심, 흥미로운 실제 문제 |
| 이번에 탐색 | 실습실·산업 후보의 확인 업무, 두 로봇 참여 가능성, 작은 시험 후보 |
| 이후 확인 | 실제 장비 기능·카메라 시야·공간·가용 인원·자료·구현 부담 |
| 합의할 준비가 됐을 때 결정 | 주제·임무·첫 완료 범위·역할·인터페이스·기술 스택 |

첫 질문은 “어디를 배경으로 삼을까?”와 함께 **“누가 무엇을 확인한 뒤 어떤 행동을 해야 할까?”**다. JetBot MINI는 활용하는 방향을 기본 전제로 기획하고, 세팅 결과에 맞춰 실제 참여 기능·임무·연동 방법을 구체화한다.

질문 전체는 [08 문서](08_DECISIONS_OPEN_QUESTIONS.md#meeting-topics), 작은 시험은 [11 문서](11_INDUSTRY_FEASIBILITY.md#tests)에서 본다. 월요일에 모든 기술적 선택을 끝내야 한다는 전제는 두지 않는다.
