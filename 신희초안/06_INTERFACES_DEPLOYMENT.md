# 연결 관계·실행 위치·배포의 검토안

이 문서는 선택지를 정리한 분석자 제안이다. 확정 상태는 [08 문서](08_DECISIONS_OPEN_QUESTIONS.md)에서 관리한다.

## 연결의 의미부터 합의한다

| 경계 | 전달할 의미 | 확인할 실패 |
| --- | --- | --- |
| ① ↔ ③ | 작업·취소 의도, 실행 단계·관측·상태·파일 | 중복·순서 역전·응답 유실·재시작 |
| ① ↔ ② | 허용된 자료 목록·같은 버전 파일, 선택한 분석 결과 | 부분 다운로드·버전 혼합·결과 중복 접수·충돌 |
| ③ ↔ 로봇 | 실제 지원 명령·피드백·단위·유효성 | 접수/완료 차이·미지원·단절·취소 |
| ② ↔ 로컬 파일·도구 | 원자료·입력/설정·파생 결과·외부 첨부 | 파일 이동·외부 변경·누락·분석 중단 |

작업·명령·시도·관측·분석 ID, 자료 버전, 시각 기준·단위, 지원·유효 여부를 필요한 범위부터 정한다. HTTP·WebSocket·ROS2·소켓 등의 채택은 의미 계약과 실제 환경 시험을 바탕으로 결정한다.

①의 DB를 클라이언트에 직접 공개하는 구조는 현재 희망에 포함되지 않는다. 허용된 업무·자료 API를 통해 접근한다.

## 실행 위치의 후보

| 위치 | 가능한 역할 | 판단할 비용·장애 범위 |
| --- | --- | --- |
| 서버 PC | ①, DB·파일 저장, 일부 ③ | 단순 배치 가능. PC 전체 중단 시 함께 멈추는 기능 확인 |
| 로봇 본체 | 장치 접근·수집·일부 실행·임시 보관 | CPU·저장·OS·권한, 단절 중 허용 동작 확인 |
| 별도 실행 PC | 일부 ③·분석·장치 연동 | 추가 관리와 네트워크 경계, 서버 중단 시 생존 여부 |
| 클라이언트 PC | ② 내부 통신·캐시·분석·결과 제출 | 앱 종료 시 작업 수명과 로컬 파일 관리 |
| 필요시 별도 상주 프로그램 | 앱 종료 후에도 필요한 수집·연동 | 실제 지속성 요구가 있는지 먼저 확인 |

이 표는 배정안이 아니다. 하나의 프로세스에 여러 책임을 넣거나 필요한 부분만 분리할 수 있다.

## 보유 사양과 두 로봇의 실행 환경

JetBot MINI는 활용하는 방향을 기본 전제로 기획한다는 최신 사용자 설명을 따른다. 세팅 확인은 실제 참여 기능과 연동 범위를 구체화하는 과정으로 둔다. 임무·담당·두 로봇의 협업 방식은 팀이 정한다.

| 근거 수준 | 현재 확인한 내용 | 남겨 둘 확인 |
| --- | --- | --- |
| 보유 장비 문서 | team_project3 README는 JetBot MINI를 Jetson Nano 4GB·TT 모터 2개·IMX219 카메라로 기록 | 실제 설치 이미지·SDK·카메라·제어·상태 조회 동작 |
| 제조사 자료 | 공식 학습 페이지에 2GB·4GB 이미지가 있고 First Trial도 두 구성을 설명 | 해당 보드·확장 보드에 맞는 자료와 이미지 선택 |
| 현재 실장비 결과 | 이번 문서 작업에서 부팅·주행·촬영 시험은 수행하지 않음 | 팀원의 세팅 결과·버전·지원 기능을 기록 |

보유 사양은 [장비 README 사본](research/team_project3_README.md)을 기준으로 참조한다. 제조사의 2GB 소개와 4GB 보유 기록을 제품 구성 차이로 해석할 근거가 생겼다. 자료에 기재된 사양과 실장비 시험 결과는 각각 표시한다. [Yahboom 공식 학습 자료](https://www.yahboom.net/study/JETBOT-mini), [2GB·4GB 공식 시작 안내](https://www.yahboom.net/public/upload/upload-html/1729154963/2.2%20First%20Trial.html)

### 필요한 기능을 환경에 맞춰 연결한다

NVIDIA의 Jetson Linux R32.7.6 안내는 JetPack 4.6.6과 Ubuntu 18.04 기반 파일시스템, Jetson Nano 지원을 설명하며 JetPack 4 계열의 최종 릴리스로 명시한다. 이는 제조사 지원 계열의 정보다. 실제 JetBot에 설치된 이미지·ROS/SDK 버전은 세팅 결과로 확인한다. [NVIDIA 공식 안내](https://developer.nvidia.com/embedded/linux-tegra-r3276)

ROS2 인터페이스 통일, 기존 SDK를 유지하는 혼합 어댑터, 조건에 맞는 ROS1–ROS2 브리지는 기존 비교안으로 둔다. 실제 연동 방식과 시험 범위는 팀이 선택한다.

Jazzy는 대화에서 한 번 언급한 선택지로만 둔다. 채택·보류·제외는 Chieftain과 Claude Code의 판단에 맡기며 관련 조사·환경 구성·이식·연동 시험을 추진하기로 정한 바는 없다.

외부 자료 확인일은 2026-11-14다. 이 자료 정리에서 로봇 실행 환경을 구성하거나 실장비 연동을 시험하지 않았다.

## Docker에서 시험할 범위

서버·DB 등에 Compose 적용을 검토한다. 환경·네트워크·볼륨·준비 검사·재시작 설정을 문서화한다. 시작 조건·컨테이너 재시작과 애플리케이션의 재연결·중복 처리·작업 복구를 각각 시험한다.

서버 프로세스 종료와 서버 PC 전원·OS 중단은 다른 시험이다. 같은 PC의 Docker도 PC 중단 중에는 실행되지 않는다. 로봇·별도 PC에서 무엇이 남는지는 실제 배치와 단절 정책으로 판단한다. 로컬 볼륨 보존과 디스크 손실 후 복원 범위도 구분한다. 기존 상세 분석에 공식 문서 근거가 있다. [Compose·복구 경계](research/feature_responsibility_analysis_2026-11-13.md#docker)

## PC 앱 환경과 공개 조건

지원 OS·CPU·런타임을 정한 뒤 소수 명령으로 환경 생성·버전 고정 의존성 설치·설정·실행을 재현하는 방향이다. 작업공간은 선택 가능한 일반 폴더로 두고 설정·캐시·로그는 사용자 환경에 맞춘다.

팀 코드의 퍼미시브 라이선스 공개는 개인 선호다. OpenCV·Matplotlib·Plotly.py·UI 라이브러리와 배포 의존성의 조건은 별도로 확인한다. 이전 검토는 OpenCV 버전별 조건, PSF 기반 Matplotlib, MIT의 Plotly.py, PySide/PyQt의 차이를 기록했다. 채택 버전·모듈·배포 방식의 재확인이 필요하다. [PC 앱 라이선스 검토](research/desktop_app_direction_2026-11-14.md#runtime) · [Matplotlib·Plotly 보완](research/personal_development_wishes_2026-11-14.md)

## 주제 선택 전에 할 작은 시험

- 실제 카메라 높이에서 대상 표시를 촬영하고 사람의 판독을 확인한다.
- 각 로봇의 입력·명령·응답·상태값과 버전을 기록한다.
- 작은 작업 자료를 다른 PC로 가져와 서버 없이 계산·재열기를 시험한다.
- 선택한 서버 장애 한 종류에서 파일과 상태의 보존·대조를 시험한다.

이는 다음 구현을 정할 시험 제안이다. 현재 통과한 결과로 해석하지 않는다.
