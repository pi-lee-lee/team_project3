## 실제 상속·호출 흐름

1. src/my_bot_fall/setup.py L6의 patrol 엔트리포인트가 fall_patrol:main을 선택한다.
2. F824–845는 FallPatrol을 만들고 3스레드 MultiThreadedExecutor를 실행한다. F32는 AStarDriver를 상속한다.
3. F79에서 부모 생성자를 호출한다. S323의 ROS 노드 이름은 astar_driver_yolo다. S446의 0.05초 타이머에는 자식의 control_loop가 연결된다.
4. S447–448의 self.setup_estop()는 F133–142를 실행한다. 부모의 모델 로딩·YOLO 워커 시작을 대신해 영상·/pose_state 구독과 감시 타이머를 준비한다. F135가 frame_timeout을 1.5초로 바꾼다.
5. F541–598은 순찰·웹·관찰·사건·대기를 처리한 뒤 F592에서 super().control_loop()를 호출한다.
6. 부모 루프의 self.motion_blocked()·self.publish_smooth()도 자식 오버라이드로 연결된다. F392–394와 F480–488이 추가 차단을 담당한다.

S의 독립 YOLO 처리 S452–618은 부모 단독 사용 경로다. 현재 patrol의 추론은 별도 lying_detector가 담당한다. S8의 PersonPatrolTest 언급과 S923 이후 시험 관련 import는 파일에 남은 설명·잔여 코드다. 현재 파일에 해당 시험 클래스나 독립 main 정의는 없다.

## 1. 지도와 A*

S59–81 make_blocked_grid는 점유격자의 0이 아닌 칸과 미확인 구역을 막고 원형 반경으로 부풀린다. S638–659 map_callback은 지도 resolution·origin을 읽고 yaw가 0이 아닌 지도를 거부한다.

S149–164 clearance_cost는 부풀린 장애물 밖의 여유 띠에 이차적으로 감소하는 비용을 만든다. 경계 바깥도 막힌 값으로 패딩한다. 이는 경로 탐색용 부드러운 추가 비용이다.

S84–146 run_astar는 8방향·octile heuristic을 쓰며 대각선 양옆이 막히면 진행을 금지한다. 이동 비용에 목적 셀의 추가 비용을 곱한다. S693–736 plan은 현재 위치와 목표를 격자로 바꿔 경로를 월드 좌표로 복원한다. 현재 위치가 부풀린 장애물 안이면 정지·실패 처리한다. find_nearest_free(S213)는 이 실행 경로에서 호출되지 않는다.

**대조할 질문** — 본인 코드의 점유값·미확인 구역 정책, footprint, 대각선 처리, 지도 원점·회전, 벽 비용 단위는 무엇인가? 복잡한 지도에서 계획 시간이 제어·정지 응답에 어떤 영향을 주는가?

## 2. 모서리를 가로지르는 추종점 제한

S271–288은 이전 인덱스 이후의 경로에서 lookahead 후보를 찾는다. S193–210 segment_clear는 선분을 resolution의 1/4 간격으로 표본화하고 대각선 교차 옆 셀도 검사한다.

S845–861 tracking_target은 후보까지의 선분이 막히면 직선으로 연결 가능한 경로점으로 줄인다. 쓸 점이 없으면 S891–896에서 정지하고 간격 조건에 따라 재계획한다. S773–784는 실제 가감속 제한 후의 명령으로 0.05초씩 10단계의 예측 이동을 검사한다.

**대조할 질문** — 현재 추종점 선택이 코너를 가로지르는가? 검사 해상도·예측 구간·불확실한 위치에서의 처리 기준은 무엇인가? 위 이산 검사는 실제 충돌 회피 성능을 실기 검증하는 근거와 구별한다.

## 3. 감속과 속도 변화 제한

S910–920은 목표까지 거리·추종 각도·전방 장애물 거리의 비율 중 작은 값을 선속도에 적용한다. 각속도 상한을 넘으면 선속도도 함께 줄여 곡률을 유지한다.

S167–173 slew는 가속·감속을 구분하며 부호 반전 시 0을 거친다. S758–788은 제한된 dt로 선속도·각속도를 갱신하고 Twist를 발행한다. S738–744의 stop_robot은 내부 마지막 명령도 0으로 초기화한다. stationary=True는 선속도를 즉시 0으로 두므로 모든 감속 상황이 정상 감속률을 따르는 것은 아니다.

**대조할 질문** — 명령의 변화량과 실제 로봇의 가감속을 어떻게 측정하는가? 목표 도착·회전·긴급 정지의 정책은 어떻게 다른가? 20Hz는 타이머 설정값이며 실제 주기 측정값은 별도다.

## 4. 회전·회피 상태 유지

S901–907은 abs(alpha)>0.8 rad에서 제자리 회전에 진입하고 0.35 rad 이하에서 해제한다. 회전 명령은 0.7×alpha를 ±0.30 rad/s로 제한한다.

S811–843은 회피 진입 시 좌·우 여유로 회전 방향을 한 번 고른다. 이후 작은 거리 변화로 방향을 바꾸지 않는다. 진입 시 정적 지도 사본에 전방 약 ±0.7 rad·1m 이내 라이다 장애물을 부풀려 추가하고 재계획한다(S242–268). 경로가 없으면 정지한다. 전방 0.43m 이상이 0.4초 유지되고 경로가 있어야 회피 상태를 푼다.

S887–889에서 전방 0.30m 미만이면 회피를 시작한다. 단, 전 방향 최근접 거리가 0.20m 이하이면 motion_blocked가 먼저 차단하여 회전도 멈춘다.

**대조할 질문** — 회피 방향·진입/해제의 깜빡임을 어떻게 줄이는가? 동적 장애물의 지도 반영·제거, 갇힘·경로 부재에 어떤 정책을 쓰는가?

## 5. 웹 정지·현재 위치에서 재개

F396–421은 setup 단계에서만 순찰 지점을 받고 마지막 지점 후 ready로 간다. F430–444 pause_drive는 drive_enabled를 끄고 현재 경로·단일 목표를 취소하되 순찰 지점과 인덱스를 보존한다.

F446–478 apply_drive_command는 명시적 run에서 현재 인덱스의 목적지를 S666–680의 목표 설정에 다시 넘긴다(F423–428). 다음 부모 루프가 현재 /amcl_pose에서 A*를 새로 계산한다. 이동 중 정지는 같은 목적지로, 도착 대기 중 정지는 F433–434에서 인덱스를 넘겨 다음 목적지로 재개한다. 목적지는 프로세스 메모리의 목록이며 프로세스 재시작 뒤 보존되는 경로가 아니다.

F702–731은 시작·복구 후 서버 run을 stop으로 초기화하고, control_epoch로 진행 중이던 이전 HTTP 응답을 무효화한다. F551–571은 사건의 웹 조치 후 조건을 확인하고 ready에서 새 시작을 기다린다. 반면 정상 자세 2초 확인은 patrol_logic.py L53–58에서 관찰→순찰 복귀를 허용한다.

**대조할 질문** — stop이 지점 목록·현재 목표·대기 인덱스 중 무엇을 보존하는가? 재시작·통신 복구 시 과거 run을 어떻게 처리하는가? 이벤트 해제와 실제 출발을 어떤 조건으로 연결하는가?

## 6. 동시 실행·센서·위치·서버 차단

S354의 RLock을 F541–598 루프, F446의 명령 적용, F480의 발행 가드, S738의 정지가 공유한다. S758도 마지막 발행 전에 차단 조건을 다시 확인한다. 부모 계획 계산도 자식 루프의 잠금 안에서 실행되므로 다른 잠금 사용 콜백이 기다릴 수 있다. S695에서 계획 전 0을 발행하지만 HTTP 정지 응답의 최대 지연을 보증하는 구조로 확대하지 않는다.

S746–755는 종료·근접 사람·비전 오류·라이다 지연/근접·영상/판정 지연을 검사한다. F392–394는 drive_enabled·phase·위치 존재·자세 건강·서버 경과를 더한다. F367–371은 자세 수신 시각과 payload stamp, camera_status, observation_valid를 검사한다. F148–161은 영상 타임스탬프와 수신 상태를 갱신한다.

**현재 확인된 한계** — F81의 localization_timeout_sec와 F36의 localization_seen은 유효성 판단에 연결되지 않는다. F144–146은 current_pose 존재만 검사하고 실제 갱신은 S661–664에서 수행한다. 따라서 한 번 받은 AMCL 위치가 오래되어도 이 검사만으로 만료되지 않는다. 실제 위치·TF freshness 정책을 이식 검토 항목으로 둔다.

**대조할 질문** — 정지 처리와 속도 명령이 같은 제어권을 사용하는가? 센서 갱신·위치 시각·서버 응답·목표 유효성이 실제 마지막 발행까지 반영되는가? 시간 기준과 잠금 범위는 무엇인가?
