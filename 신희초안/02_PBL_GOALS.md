# PBL 목표와 단계별 완결성

## 먼저 확인할 실제 문제

설명용 문제는 여러 장소의 화재 위험 관련 상태를 확인하고, 이상 신고 후 현장 증거와 후속 행동을 연결하는 업무다. 확인할 항목은 장비 표시·외관·통로 등에서 구체화한다. 담당자의 이동·확인·기록 부담, 퇴실·인계 누락, 불분명한 관측의 후속 처리에 실제 불편이 있는지 조사한다. 실습실과 산업 현장 모두 문제 가설로 검토하며 실제 사용자 확인 전에는 수요를 단정하지 않는다.

확인할 질문은 다음과 같다.

- 누가 무엇을 보고 어떤 결정을 내려야 하는가?
- 현재는 직접 방문·고정 카메라·기존 관리 프로그램으로 어떻게 처리하는가?
- 관측이 오래되거나 사진이 불분명할 때 어떤 손실이 생기는가?
- 이동 로봇의 접근·촬영이 기존 방식보다 도움이 되는 조건은 무엇인가?
- 한 번의 확인 실패가 어떤 후속 요청과 기록으로 연결되어야 하는가?

## 화재 관련 관심을 세 가지 목표로 나눈다

| 목표 후보 | 해결하려는 확인·행동 | 작은 검증 결과 | 추가로 확인할 부분 |
| --- | --- | --- | --- |
| 예방을 위한 점검 지원 | 장비 표시·외관·통로 등 정한 항목의 확인 누락 줄이기 | 항목별 증거·사람 판단·미확인 사유 | 실제 화재 위험과의 관련성·기존 점검 대비 가치 |
| 이상 징후 관측·재확인 | 모의 경보 또는 관측 요청이 발생한 지점 추가 확인 | 해당 지점·시각의 관측과 경보 연결 | 실제 열·연기·가스 감지는 맞는 센서·정답·별도 평가 |
| 모의 사고 대응 | 모의 신고 뒤 후속 행동을 요청하고 수행 결과 확인 | 조치 요청·실행/미완료 이력, 선택한 비위험성 장치 시험 | 장치의 업무 필요성·기구·시험 공간·중지 조건 |

이 세 목표는 같은 사건 흐름에서 연결할 수 있다. 경고등 사진 확보, 내부 발열 감지, 표적에 대한 모형 장치 작동은 각기 다른 성과로 기록한다. 모의 표적 인식·명중 결과에서 실제 화재 조기 감지·소화 효과를 추정하지 않는다.

모형 대응에 관심을 가진 팀원의 아이디어도 후보로 유지한다. 채택 시 사람과 분리된 통제 공간·저위험 모형·범위 제한·오작동 시 중지를 검토하고, 화염·유해 연기·손상 배터리 없이 작업 흐름을 시험한다. 장치가 완성되기 전에도 선택한 점검·재확인 업무가 끝나도록 단계의 경계를 둔다.

## 실습실에서 PBL을 확인하는 방법

실습실을 배경으로 택하려면 실제 이용자·관리자에게 어떤 퇴실·점검·인계가 반복되며 무엇이 누락되는지 먼저 확인한다. 장비의 표시가 관측되는지와 실제 전원·내부 상태를 알 수 있는 범위도 구분한다. 체크리스트·고정 카메라·직접 방문과 비교해 로봇 이동으로 추가되는 정보가 있는지 시험한다.

산업 모형을 실습실에 설치하는 경우에는 현장 사용자를 가정한 근거와 재현한 조건을 적는다. ‘실습실은 PBL이 약하다’거나 ‘산업 배경이면 PBL이 성립한다’는 결론을 미리 두지 않는다. [실습실과 산업 배경 비교](09_INDUSTRY_MEETING_BRIEF.md)

## 이동성의 필요성을 시험한다

여러 위치에서 가까이 촬영할 필요, 고정 카메라의 시야와 설치 부담, 로봇 카메라 높이·접근 가능성을 비교한다. 고정 카메라로 같은 업무가 충분히 끝난다면 이동 로봇의 효용을 다시 평가한다. 모형에서 확인한 결과와 실제 시설 적용 결과를 각각 기록한다.

## 세 수준의 완료 기준 제안

| 수준 | 끝나는 사용자 업무 | 검증과 남는 성과 |
| --- | --- | --- |
| 최소 완결형 | 한 점검 요청을 받아 실제 관측·저장·조회·사람 확인까지 완료 | 대상·촬영 시각·근거가 연결되고 실패·확인 불가도 보고되는 원격 확인 업무 |
| 기술적 심화형 | 확보 자료의 반복 분석·후속 점검·선택한 장애 복구까지 완료 | 입력·설정·결과 재현, 오류·누락 감소, 복구 후 상태 대조를 평가할 소프트웨어와 시험 결과 |
| 도전적 확장형 | 품질 검사·자동 판정·재촬영 정책·ML 등을 추가 | 기본 방법과 같은 조건에서 비교하고 기존 관측·분석 기능을 유지 |

개인 PC 모듈의 독립 성과는 한 자료 묶음을 분석하고 결과를 다시 여는 것으로도 성립할 수 있다. 팀의 로봇 PBL 성과는 실제 관측 업무와 연결한 뒤 평가한다. 설치·토픽 수신·DB 연결·Docker 기동은 준비 결과로 기록한다.

## 비교할 대안과 측정 계획

| 비교 질문 | 대안 | 측정할 항목 |
| --- | --- | --- |
| 확인 업무가 편해지는가? | 직접 방문·고정 카메라·이동 관측 | 올바른 확인 여부, 소요 시간, 사람의 개입, 미확인 항목 |
| 조사·분석이 재현되는가? | 수동 파일 찾기·기존 도구·PC 앱 | 근거 누락, 같은 입력의 계산 결과, 보고 완료 과정 |
| 후속 점검이 도움이 되는가? | 단일 촬영·사람 요청 재촬영·선택적 품질 규칙 | 판독 가능률, 불필요한 재촬영, 놓친 불량 관측 |
| 복구 정책이 유효한가? | 정상·선택한 장애 조건 | 예상/등록 자료 대조, 중복, 불명확 실행, 복구 후 상태 |

실제 시험 전에 성능 수치·필요 데이터 수·소요 기간을 확정하지 않는다. 데이터·정답·조건·실장비 여부를 함께 남긴다.

## 기능을 채택할 기준

각 기능에 사용자·입력·출력·비교 대안·작은 완료 기준을 적는다. 가장 어려운 기능을 완성하지 못했을 때도 끝낼 수 있는 업무가 있는지 확인한다. 확장 기능은 기존 결과를 보존하는 입력·출력 경계를 갖도록 검토한다.

개별 후보는 [07 문서](07_FEATURE_CANDIDATES.md), 채택 상태는 [08 문서](08_DECISIONS_OPEN_QUESTIONS.md)에서 확인한다.
