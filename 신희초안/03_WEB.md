# ① 웹 서비스

## 개인 희망

다른 컴퓨터의 사용자가 브라우저 등을 통해 허용된 업무 기능에 접근하는 영역으로 구상한다. 프론트엔드·백엔드·DB를 포함한다. 백엔드가 권한·업무 규칙·공식 기록을 관리하고 허용한 API를 제공한다.

## 기능 후보와 작은 완료 기준

| 후보 | 직접 개발할 처리 | 작은 완료 기준 |
| --- | --- | --- |
| 1·9 요청과 진행 | 요청 검증, 작업 ID, 실행 보고 반영, 단계·마지막 확인 표시 | 한 요청의 실제 결과와 멈춘 단계를 조회 |
| 2·4 근거와 후속 확인 | 사진·항목 연결, 사람 확인, 미확인 사유, 재점검 이력 | 확인 불가에서 후속 관측·결론까지 추적 |
| 3·5 비교와 갱신 | 이전 관측 조회, 촬영·수신 시각, 현재성 표시 | 오래된 관측을 구별하며 상태 변화 검토 |
| 25 자료 제공 | 접근 가능한 자료 목록·버전·파일 제공 | PC가 한 작업의 같은 버전 자료를 확보 |
| 26 분석 접수 | 제출 ID·입력 참조·결과 저장, 중복·충돌 처리 | 제출 결과가 원자료와 연결되어 웹에서 조회 |
| 12·13 취소·전환 | 의도 접수, 실행 응답 확인, 미완료 보존 | 요청과 실제 적용 결과를 각각 확인 |

번호별 설명과 채택 상태는 [07 문서](07_FEATURE_CANDIDATES.md)에서 관리한다. 개인 담당은 미정이다.

## 화면과 실제 처리의 연결

브라우저는 사용자의 의도와 서버가 확인한 상태를 표시한다. DB 접근은 백엔드의 허용된 경로로 처리한다. 작업 버튼을 누른 시각, 실행 접수, 관측 완료, 사람의 확인은 각각의 사실로 기록한다.

③은 실제 장치 피드백과 실행 결과를 보고한다. ①의 공식 업무 기록과의 대조 원칙은 [05 문서](05_SYSTEM_COMMUNICATION.md)에서 본다.

## PC 앱과 공유할 부분

자료 조회·다운로드·분석 결과 API는 공통으로 활용할 수 있다. 같은 사진·그래프를 양쪽에서 보여 주어도 실제 이용 장면과 편의성이 있으면 검토한다. 수정 권한·원본·현재 상태의 의미를 맞추고, 두 UI의 중복 유지비를 비교한다.

## 아직 선택할 부분

사용자·권한 범위, 공식 확인 절차, 조종 화면 위치, 프레임워크·DB·API 방식은 팀이 정한다. 기존 Java·Spring Boot·Next.js 경험은 선택 근거로 검토하되 현재 숙련도와 분업을 함께 확인한다.
