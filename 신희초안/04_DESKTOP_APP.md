# ② 독립 PC 앱

## 존재 이유와 개인 희망

서버의 사진·센서·로그·작업 기록을 일반 로컬 폴더에 가져와, 확보한 자료를 서버 연결 없이 다시 열고 반복 분석·정리하는 작업공간을 원한다. PC의 라이브러리·연산 자원·기존 프로그램을 활용해 분석 결과와 설정을 보존하고 필요한 결과를 서버에 제출한다.

## 1순위와 보조 후보

| 관심 수준 | 기능 | 쓰임 |
| --- | --- | --- |
| 1순위 개인 희망 | 25 자료 가져오기·일반 폴더·오프라인 재열기 | 서버 자료와 여러 작업을 내 PC에서 관리 |
| 1순위 개인 희망 | 로컬 계산·반복 분석·설정/결과 연결 | 같은 입력에 기준을 바꾸며 비교하고 재현 |
| 1순위 개인 희망 | 27 외부 앱·코딩 에이전트 활용 | 기존 도구의 결과를 원작업과 연결 |
| 1순위 개인 희망 | 26 결과 보존·선택 제출 | 완료한 로컬 작업을 공유 기록에 연결 |
| 보조·확장 희망 | 상태 표시·로그·그래프·실패 조사·서버 자료 조회 | 위 작업을 돕거나 별도 사용 편의 제공 |

이 우선순위는 관심의 무게다. 엄격한 개발 순서를 정하지 않는다. 기능이 웹·Foxglove와 겹쳐도 실제 사용자 작업을 더 편하게 끝낼 수 있다면 포함할 수 있다. 구현 중복·유지비도 함께 평가한다.

## 대표 사용 장면 — 세 차례 점검 자료의 반복 분석

아래는 기능 가치를 설명하는 가상 시나리오다. 실습실·공장 등 어느 배경을 택하더라도 같은 지점을 반복 촬영하는 업무에서 검토할 수 있다.

1. 서버에서 같은 지점의 세 차례 점검 사진·로그·센서 기록을 골라 로컬 작업공간으로 가져온다.
2. 확보한 자료의 지점·로봇·촬영 시각·원본 목록을 확인하고 서버 연결을 끊는다.
3. OpenCV로 동일한 관심 영역의 밝기·색상 지표를 계산하고 Matplotlib로 방문별 차이를 그린다.
4. 기준이나 관심 영역을 바꿔 반복 계산하고, CSV를 스프레드시트에서 확인하거나 허용된 파일·코드를 Codex·Claude Code로 검토한다.
5. 각 실행의 입력·설정·도구 버전·결과를 보존한다. 앱을 다시 열어 같은 근거를 확인하고 필요한 결과만 서버에 제출한다.

밝기·색상 차이는 조명·노출·촬영 자세에도 영향을 받으므로 실제 장비 상태 변화와 대조해야 한다. 다른 구도의 영역을 바로 비교할 수 있는지도 먼저 시험한다. 분석 계산·변화 해석·최종 사람 판단을 각각 기록한다.

첫 시험 후보로 고정된 샘플 자료의 처리를 제안한다. 채택할 경우 샘플 처리·실장비 자료 분석·서버 연동의 성공 여부를 각각 기록한다. 이번 자료 정리에서는 해당 앱을 구현하거나 시험하지 않았다. 반복 처리·파일 정리·외부 도구 활용의 실용성은 선택한 업무에서 확인할 질문이다.

## 가장 작은 완결형의 제안

1. 작업 한 건의 사진·이벤트·센서 CSV와 자료 목록을 서버에서 가져온다.
2. 사용자 폴더에 보관하고 누락·버전을 확인한다.
3. 실제 로컬 계산 한 종류를 실행한다.
4. 입력·설정·도구 버전·결과 파일을 연결해 저장한다.
5. 서버 연결을 끊고 앱을 재실행해 이전 결과를 확인한다.
6. 필요하면 결과를 선택 제출한다. 제출은 후속 완료 단위로 나눌 수 있다.

### 첫 분석으로 시험할 두 후보

| 후보 | 입력과 계산 | 출력·확인 |
| --- | --- | --- |
| 센서 수신 간격 조사 | 같은 수집기의 수신 시각으로 인접 간격·기준 초과 구간 계산 | CSV·Matplotlib 그래프, 알려진 시험 파일과 계산값 대조 |
| 사진 ROI 밝기 분석 | OpenCV로 관심 영역의 밝기 통계·어두운 영역 비율 계산 | 특징 CSV·설정·이미지, 기준 계산 및 다른 촬영 조건 대조 |

Matplotlib은 계산 결과를 그리는 역할을 맡는다. 센서 공백은 고장 원인 확정과 구별하고, 밝기 지표의 판독 가능성은 사람의 평가와 비교한다. 종류·기준은 분석자 제안이며 선택 전이다.

## 폴더와 외부 프로그램

원자료 사본을 보존하고 분석 실행별로 파생 결과를 둔다. 필요한 메타데이터는 작업/관측 ID, 자료 버전, 파일 상대경로·해시, 단위·시각 기준, 입력 목록, 설정·분석 버전, 완료·중단 상태 등이다. 정확한 폴더명·스키마는 미정이다.

이미지 편집기·스프레드시트·에디터로 파일이나 사본을 열고 결과 파일을 선택해 다시 연결한다. 실행 요청 성공과 외부 편집 완료를 구분한다. 파일 이동·크기 변경·누락·한글 경로를 시험한다.

Codex·Claude Code는 허용된 폴더의 안내·CSV·JSON·Markdown 등과 분석 코드를 활용하는 선택적 외부 도구로 고려한다. 이미지·바이너리 기록은 지원 도구·판독기를 확인한다. 원인 해석은 계산값·시험 근거와 대조한다. 앱의 오프라인 분석과 에이전트의 모델 접속·자료 전송 조건은 별도로 확인한다.

### 작업공간 한 개의 파일 예시

형식 논의를 돕는 예시다. 폴더명·JSON 필드·실행 방식의 확정안은 아니다.

```text
workspace/
  job_001/
    manifest.json
    original/
      observation_01.jpg
      observation_02.jpg
      sensors.csv
      events.json
    analysis/
      experiment_01/
        parameters.json
        inputs.json
        result.csv
        chart.png
        notes.md
```

manifest에는 서버 자료·작업·지점·로봇 ID, 자료 버전, 촬영/수신 시각, 파일 상대경로·해시·모의/실측 구분을 검토한다. 분석 실행에는 사용한 입력 목록·해시·설정·도구 버전을 연결한다. 로컬 초안과 서버가 접수한 결과를 구별해 저장한다.

서버의 원자료가 바뀌어도 확보한 입력 사본으로 이전 계산을 재현할 수 있는지 시험한다. 다른 PC로 폴더를 옮겨 경로를 확인하고, 제출 시 서버 버전과 다르면 로컬 초안을 보존한 채 후속 처리를 선택한다. 처음부터 자동 동기화를 의무화하지 않는다.

에이전트 연계는 선택한 로컬 자료를 도구가 활용하는 구상이다. 파일 접근 권한과 모델 접속·외부 자료 전송 조건은 사용 도구와 환경에서 확인한다.

## 온라인과 오프라인

확보한 파일의 조회·계산·메모·결과 저장은 서버 없이 완결하도록 검토한다. 최신 목록·현재 로봇 상태·추가 다운로드·결과 제출은 서버 연결이 필요하다. 확보 시각과 버전을 표시한다.

로컬 분석은 초안·파생 결과로 관리한다. 서버 제출과 공식 업무 결과 수정은 각각의 절차로 처리한다. 원자료·다른 사용자 변경과 충돌하면 초안을 보존하고 선택적으로 반영한다. 처음에는 수동 제출과 버전 확인으로 시작하는 제안이다.

## 실행·구현 경계

앱 사용 중 다운로드·캐시·분석·업로드는 ② 내부에서 처리할 수 있다. 앱 종료 후에도 계속 필요한 수집·통신이 생기면 별도 프로그램을 검토한다. 서버 API 이용을 우선하고, 로컬 상주 에이전트·ROS2 전체 설치는 현재 우선하지 않는다.

UI 기술·대상 OS는 미정이다. 소수 명령으로 환경·의존성·설정·실행을 재현하고 개인 절대경로 의존성을 피하는 방향이다. 라이선스와 배포 선택지는 [06 문서](06_INTERFACES_DEPLOYMENT.md)에서 본다.
