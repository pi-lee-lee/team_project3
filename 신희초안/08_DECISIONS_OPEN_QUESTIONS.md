# 결정 상태·미결정 사항·문서 간 차이

2026-11-16 회의 전 전달본이다. 이 파일을 상태 기록의 기준으로 삼고, 회의 후 결정 근거·일자·참여자를 추가한다.

## 상태의 의미

- **자료에서 확인** — 해당 파일·공식 문서에 적힌 내용이다. 실장비 검증은 별도 표시한다.
- **개인 희망·사용자 조건** — 사용자가 이번 요청과 이전 대화에서 밝힌 방향이다.
- **분석자 제안** — AI 분석이 제시한 기능·책임·단계·시험이다.
- **팀 미결정** — 채택·담당·설계에 관한 팀 합의 근거가 확인되지 않았다.

## 준비한 방향과 팀이 함께 결정할 범위

PBL·단계별 완결성, ① 업무·기록 서비스, ② 로컬 작업공간·반복 분석, ③ 실행·수집·통신의 희망을 구체화했다. 이 방향과 기능 후보를 팀에 제안하고, 실제 개발 범위·임무·실행 위치·스택·분업을 함께 정한다. 아래 열린 항목은 공유·탐색·검증·추후 합의할 대상을 구별해 제시한다. 팀 확정을 증명할 회의록은 현재 자료에 없다.

| 열화상 | 기존 장비·팀 합의 미확정 | 필요성·비용·구현·시험 범위 |

최신 맥락의 1차 근거는 패키지 제작 요청과 이후 사용자 추가 설명이다. JetBot MINI는 사용할 가능성이 매우 높아 활용을 기본 전제로 기획한다. Jazzy는 한 번 언급한 선택지로 두며, Chieftain과 Claude Code가 제외할 수 있다. 이를 개발 계획이나 시험 약속으로 확대하지 않는다. 이전 요약 파일은 [개인 희망 요약](research/personal_development_wishes_2026-11-14.md), [PC 보완](research/desktop_app_direction_2026-11-14.md)에서 찾을 수 있다.

## 기존 문서의 차이와 이번 전달본의 처리

| 차이 | 원문에서 찾을 위치 | 이번 전달본의 처리 |
| --- | --- | --- |
| 실습실이 첫 시나리오의 기본 배경으로 등장 | 이전 통합안·초기 회의 요약 | 실습실을 포함한 11개 배경을 유지하고 첫 설명은 장소를 열어 둠 |
| 화재 관련 점검·감지·대응이 넓게 연결됨 | 초기 시나리오·산업 제안 | 실제 확인 업무와 관측 수단·모의 후속 행동을 구분해 선택 |
| 다섯 영역을 ‘필수·팀 목표’처럼 표현 | 통합 첫 회의안·초기 기능 탐색 | 개인의 강한 희망으로 표시하고 팀 채택은 미결정 |
| PC 앱을 진단 중심으로 좁힘 | 통합안의 PC 메뉴·책임 제안 | 로컬 작업공간·반복 분석을 중심 희망으로, 진단은 보조 후보로 유지 |
| 첫 PC 단계가 가져오기·조회·보고에 치중 | PC 보완의 단계 표 | 실제 계산 한 종류를 포함한 완료 단위를 제안 |
| 별도 상주 에이전트·ROS2 설치를 우선하지 않음 | PC 보완의 실행 조건 | 현재 우선 검토 방향으로 보존. 앱 종료 후 지속 요구가 확인되면 별도 프로그램 검토 |
| 서버/실행 프로그램을 단순히 양분 | 이전 구조도·설명 | ①의 백엔드 처리도 명시하고 ③의 수·위치와 내부 API는 열어 둠 |

| 보유 Nano 4GB 기록과 제조사 2GB 소개 | 보유 장비 README·이전 책임 분석 | 공식 자료에 2GB·4GB 구성이 모두 있다. 보유 문서의 4GB를 기준으로 참조하고 설치 이미지·기능은 세팅 결과로 확인 |
| JetBot을 세팅 성공 후의 조건부 참여로 설명 | 이전 요약·연구 사본 | 최신 사용자 설명에 따라 활용을 기본 전제로 기획하고 실제 임무·연동 범위를 확인 |
| 엔코더 부재에서 카메라 위치 추정만 필요하다고 서술 | 장비 README 마지막 문장 | 사용 센서·외부 기준·임무에 따라 선택할 문제로 남김 |

작업공간 원본은 보존한다. 전달용 연구 사본에는 참고용 안내와 링크·경로·오타 정리를 적용했다. 이 표의 해석과 실장비 검증 결과는 구별한다.

## 공유·탐색·검증·추후 합의할 질문

월요일은 개인 희망과 문제 후보를 공유하는 자리로 구상한다. 기술적 선택은 근거와 합의의 준비 정도에 따라 진행한다.

| 시점 | 논의할 질문 |
| --- | --- |
| 이번에 공유 | 각자 어떤 문제·기능을 해 보고 싶은가? 개인 희망 중 특히 맡아 보고 싶은 책임은 무엇인가? |
| 이번에 탐색 | 누가 어떤 확인·분석 업무를 끝내야 유용한가? 실습실·산업 배경 중 어디에서 관측 대상을 찾을까? |
| 이번에 탐색 | 화재 관련 점검·재확인·모의 대응 중 중심 문제는 무엇인가? 자동 판정·투척·열화상은 어떤 가치를 더할까? |
| 이번에 탐색 | 두 로봇은 어떤 서로 다른 정보·업무를 제공할 수 있을까? 첫 웹 업무·PC 분석·③ 실행의 작은 완료 모습은 무엇일까? |
| 이후 확인 | 대상은 실제 카메라 높이·주행 환경에서 관측 가능한가? JetBot 세팅과 각 로봇의 기능을 어떤 자료로 확인할까? |
| 이후 확인 | 실제 보드·메모리·OS·카메라·구동·제어 API·상태 조회 중 확인된 범위는 무엇인가? |
| 이후 확인 | 어떤 프로세스/PC 장애를 먼저 시험할까? 대상 OS·UI·언어·통신·배포·라이선스는 어떤 시험과 자료로 비교할까? |
| 합의할 준비가 됐을 때 | 팀이 채택할 주제·임무·기능·담당·첫 완료 기준을 어떻게 정할까? |
| 합의할 준비가 됐을 때 | 자료 형식·촬영/수신 시각·단위·ID·원본/분석 버전은 어떻게 맞출까? |
| 합의할 준비가 됐을 때 | 조종 화면·제어권·단절·취소·불명확 실행 정책, 프로그램 위치·복구·보존 범위를 어떻게 정할까? |

두 로봇의 참여 방식을 임의로 정하지 않는다. JetBot의 지원 기능이 다르면 추가 관측·별도 지점 확인 등 실제 가치가 있는 역할 후보를 비교한다. 협업 주행·임무 인계의 필요성도 함께 검토한다.

## 장비·실행 환경의 현재 근거

보유 장비 README는 JetBot MINI를 Jetson Nano 4GB로 기록하며, 전달용 사본 본문도 현재 원본과 일치한다. 제조사도 2GB·4GB 구성의 시작 안내와 이미지를 제공한다. 설치 OS·ROS/SDK·드라이버·제어·촬영의 동작 확인을 별도 기록한다. 보유 장비 환경의 근거와 선택지는 [06 실행 환경](06_INTERFACES_DEPLOYMENT.md#robot-environments)에서 확인한다.

[주행 부록](appendix/driving_reference/README.md)은 필요할 때 세부 값·처리 방식을 참고할 자료다. Chieftain의 기존 코드를 중심으로 진행하려는 최신 구상을 반영한다. Chieftain의 코드가 아직 제공되지 않아 비교 결과나 교체·통합 결론은 내리지 않았다.
