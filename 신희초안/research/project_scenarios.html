후보 1 · 닫기 전에, 정말 확인했나요?

이용자와 문제

공동 실습실 관리자가 퇴실 전에 장비 여러 대의 표시 상태를 확인해야 한다. 장비는 서버와 연결되어 있지 않고, 관리자는 매번 장소를 돌며 사진과 체크리스트를 남긴다. 한 장비의 표시창이 가려졌는데도 점검 완료로 처리되면, 기록의 신뢰성이 떨어진다.

핵심 질문은 어느 정도의 관측을 확보해야 확인했다고 말할 수 있는가다. 한 번 촬영하기, 여러 프레임을 비교하기, 다른 위치에서 재촬영하기, 사람에게 확인을 요청하기 중 어떤 방법을 언제 선택할지 팀이 정한다.

이동 로봇이 필요한 조건

여러 위치에 있는 표시창을 가까이서 확인해야 하고, 고정 카메라를 각 위치에 설치하기 어려운 환경을 가정한다. 실제 표시창의 높이와 카메라 시야가 맞아야 한다. 적은 수의 고정 카메라로 같은 업무를 충분히 수행할 수 있는 현장이라면 이동형 방식의 이점을 다시 평가한다.

산 중턱 1 — 두 장소의 점검을 끝내고 근거를 제공

관리자가 두 장비를 선택하면 로봇이 정해 둔 촬영 위치로 이동한다. 카메라로 장비 ID와 지정 표시 영역을 확인하고, 사전에 정의한 색상·도형 상태를 판정한다. 각 결과에 촬영 시각·사진·판정 근거를 연결해 보고서를 제공한다. 가림이나 판독 실패는 확인 요청으로 남긴다. 실제 장비의 녹색 표시가 무엇을 뜻하는지는 장비별로 정의해야 한다.

첫 시연은 장비 A는 정상 표시, B는 이상 표시인 조건에서 두 결과와 사진이 정확하게 연결되는 모습을 보여 준다. B를 가리면 보고서에 확인 요청이 남아야 한다. 모의 패널을 사용한 단계에서는 해당 패널의 시각 상태를 판정한 성과를 기록한다.

산 중턱 2 — 확인 불가와 오판을 줄이는 재관측

영상 밝기·선명도·표시 영역 가림 등을 기준으로 재촬영을 결정한다. 처음에는 같은 자리에서 다시 촬영하는 방법을 구현하고, 유효한 관측 위치가 확보되면 사전 등록한 다른 위치로 이동하는 방법을 비교한다.

한 번 촬영과 재관측 정책을 동일한 장비 상태·조명·가림 조건에서 시험한다. 잘못 정상으로 판단한 비율, 확인 불가 비율, 추가 소요 시간, 사람의 재확인 건수를 함께 측정한다. 확인 불가만 줄이려다가 오판이 늘어나는지도 살핀다.

정상 — 새로운 표시를 다루거나 관측 위치를 선택

숫자 표시 판독, 간단한 학습 기반 상태 분류, 다음 촬영 위치 선택을 확장으로 검토한다. 새 모델이 충분한 성능을 내지 못하면 검증된 표시 유형과 기존 관측 정책으로 점검을 계속 제공한다.

데이터·Docker·개인 구현 성과

  • 데이터는 팀이 상태를 설정할 수 있는 인쇄 패널이나 PC 화면에서 시작한다. 정답 상태와 조명·거리·촬영 회차를 별도로 기록한다. 화면 촬영은 반사·모아레도 확인한다.

후보 2 · 도착했는데, 전달은 끝난 걸까요?

이용자와 문제

실습실과 사무실 사이에서 작은 물품을 옮기는 담당자가 있다. 사람이 물품을 로봇에 올리고 목적지를 지정했지만, 도착한 곳에 수신자가 없거나 전달 확인이 늦어진다. 관리 화면에 도착만 표시되면 담당자는 실제 전달 여부를 다시 확인해야 한다.

핵심 질문은 사람의 행동과 로봇의 이동이 섞인 업무를 어떤 근거로 완료 처리할 것인가다. 대기 후 재알림, 수신자 재지정, 복귀 요청 등 대안을 비교할 수 있다.

실제 병원에서도 물품·검체·약품 운송을 로봇에 맡긴 사례가 있다. 여기서 제안하는 범위는 실습 공간의 가벼운 물품 운송과 사람의 인계 확인이다. ThedaCare의 로봇 운영 사례

이동 로봇이 필요한 조건

서로 떨어진 장소 사이에서 물리적인 물품을 옮기는 수요가 있어야 한다. 이동 가능한 단층 구역과 열린 출입 경로를 우선한다. 적재물의 고정과 로봇의 실제 적재 가능 조건을 확인한다. 자동 적재·하역은 첫 범위에 포함하지 않는다.

산 중턱 1 — 한 건을 운송하고 전달 결과를 남김

요청 등록 → 적재 담당자 확인 → 실제 목적지 이동 → 수신자 확인 → 최종 결과 기록까지 완성한다. 수신 확인에는 웹의 작업별 확인 버튼 같은 단순한 방식을 사용할 수 있다. 도착 후 제한된 대기 동안 확인이 없으면 미전달 상태와 사유를 기록하고 다음 조치를 담당자에게 요청한다.

시연은 정상 인계 한 번과 수신자 부재 한 번이다. 두 경우 모두 작업이 어떤 상태로 끝났는지 확인할 수 있어야 한다. 이 단계만으로 담당자가 물품의 진행 상황과 후속 조치를 파악할 수 있다.

산 중턱 2 — 응답이 사라져도 작업 이력을 지킴

작업 ID, 허용 상태 전이, 이벤트 순서, 재시도와 중복 처리 정책을 설계한다. 시험에서는 로봇의 주행 통신을 유지한 채 서버 API 응답 유실·서버 재시작을 주입한다. 전달 확인을 처리한 뒤 응답만 유실된 경우에도 같은 요청을 재처리했을 때 결과가 일관되는지 확인한다.

한 작업이 중복 실행된 횟수, 재연결 후 상태 수렴 시간, 사라진 이벤트 수, 잘못된 완료 판정 건수를 측정한다. 로봇의 물리적 행동과 서버 기록 사이에서 보장할 수 있는 범위를 명시한다.

정상 — 여러 작업의 우선순위와 전환 정책

긴급 요청, 여러 목적지, 적재된 물품의 제약을 고려한 순서 결정을 추가한다. 확장 기능은 이미 물품을 싣고 있는 작업을 언제 바꿀 수 있는지 정책을 정의한 뒤 적용한다. 확장을 중단하면 단일 작업 수행과 검증된 재시도 기능이 남는다.

데이터·Docker·개인 구현 성과

  • 실제 물품·작업 ID·적재 확인·수신 확인·이동 결과·오류 주입 기록이 평가 자료다. ML 학습 데이터가 없어도 전체 업무를 완성할 수 있다.
  • 카메라는 인계 위치나 물품 사진을 남길 필요가 생기면 활용한다. ML의 우선순위는 낮다.

  • 개인이 작업 상태 모델, ROS2와 서버 사이의 명령·결과 처리, 재시도 정책, 장애 시험을 책임질 수 있다. 직접 소켓을 구현할지는 실제 통신 요구와 지원 직무를 보고 정한다.

후보 3 · 실습을 시작하려는데 필요한 물품이 없어요

이용자와 문제

이동 로봇이 필요한 조건

물품이 여러 보관 지점 사이에서 이동하고, 로봇 카메라로 접근 가능한 높이에 놓여 있어야 한다. 표식이 보이는 정해진 보관 영역부터 시작한다. 닫힌 서랍이나 높은 선반 안쪽의 물품은 관측 범위에서 제외한다.

산 중턱 1 — 필요한 목록과 현장을 대조

관리자가 필요한 물품 세 개와 보관 지점 세 곳을 등록한다. 숫자는 최초 시험 구성을 위한 제안이다. 로봇이 지정 지점을 방문해 물품에 부착한 식별표를 확인하고, 발견 위치·시각·사진을 목록에 연결한다.

보고서는 확인한 물품과 관측 범위에서 미확인인 물품을 제공한다. 모든 지정 지점을 돌았는데 보이지 않은 경우에도 실제 부재를 단정하지 않는다. 이 결과로 조교는 남은 항목을 직접 확인할 수 있다.

물품을 원래 장소에서 다른 지점으로 옮겨 두고, 로봇이 실제 확인 위치를 보고하는 장면을 시연한다. 첫 단계에서는 물품 자체에 부착한 표식을 식별한다. 보관함의 표식만 읽은 결과로 물품 존재를 판단하지 않는다.

필수 물품을 모두 확인하면 남은 방문을 생략하거나, 우선순위가 높은 항목을 먼저 확인하는 전략을 구현한다. 고정 순서와 개선 전략을 동일한 물품 배치·가림 조건에서 비교한다. 과거 위치 정보가 틀린 시험도 포함한다.

필수 물품 확인까지 걸린 시간, 방문 수, 이동 거리, 잘못된 물품 확인, 사람의 후속 확인 건수를 측정한다. 알고리즘이 항상 우수하다는 가정 없이 효과가 생기는 조건과 불리한 조건을 조사한다.

기존 프로젝트 인수인계 문서에는 순찰·웹 정지의 확인 기록과 함께 간헐적인 통신 지연, 일부 미검증 통합 흐름이 남아 있다. 이 기록은 반복 시험의 필요성을 검토할 구체적인 출발점이다. 현재 같은 문제가 재현되는지는 확인하지 않았다. 기존 실기 확인 및 미해결 기록

산 중턱 1 — 정해진 시험 임무와 보고서

정해진 출발 위치에서 지정 지점으로 이동하고, 정지를 확인하고, 지정 표식을 촬영한 뒤 시험 결과를 제공한다. 기준은 시험 전에 정한다. 이동 위치는 바닥 표시와 관찰 기록 등 독립적인 기준으로, 표식은 알려진 ID로 대조한다. 정지 확인에는 로봇 로그와 관찰 영상을 함께 검토할 수 있다.

보고서에는 통과·실패·측정 부족으로 판정 불가인 항목과 로그·사진을 연결한다. 첫 결과의 의미는 해당 조건의 시험 임무 수행 여부다. 배터리·LiDAR·카메라 등 확인한 항목별로 근거를 남긴다.

산 중턱 2 — 재현 가능한 실패를 찾아냄

알려진 기록 데이터에 영상 누락·오래된 타임스탬프·처리 지연을 주입해 검출 로직을 검증한다. 실제 주행에서의 결함 시험은 시험용 데이터 경로와 제어 경로를 구분하고 정지·감독 절차를 갖춘 상태에서 설계한다.

정상 시험을 잘못 실패로 판단하는 비율, 주입한 문제의 검출률, 재시험 결과 일치, 원인 조사에 필요한 정보의 누락을 측정한다. 실제 주행 시험과 기록 재생 시험을 보고서에서 구별한다.
