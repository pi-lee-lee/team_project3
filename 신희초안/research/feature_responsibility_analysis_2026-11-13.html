서로 다른 PC의 monotonic 시간은 직접 비교하지 않는다. 갱신 간격은 같은 수집기의 시간으로 측정하고, 장치 시각과 수신 시각을 보존한다. 다중 호스트 시간축을 정밀 비교할 때는 시계 동기화·오차 범위를 추가로 검증한다. 수신 순번은 한 부팅 구간의 순서를 나타내며 전체 장치의 전역 시각을 대체하지 않는다.

복구 시 대조할 순서

  1. 실행 프로그램이 재시작되면 로컬 명령·관측 기록과 실제 장치의 조회 가능 상태를 읽는다. 서버는 마지막 저장 업무·버전을 읽는다.
  2. 완료한 관측·이벤트를 고유 ID로 전달하고 서버가 파일·메타데이터 저장을 검증해 확인한다. 관측 재전송은 같은 관측 ID를 사용한다.
  3. 진행 중·취소 요청·실행 불명확 기록을 대조한다. 오래된 요청은 유효성·현재 작업 버전·제어 주체를 확인한 뒤 처리한다.
  4. 기존 명령의 실행 여부가 불명확한 물리 동작은 확인 필요로 남긴다. 재실행은 원명령을 조회·정리한 뒤 명시적 새 시도로 처리하는 정책을 권한다.

파일 보존과 DB 반영 사이에도 중단이 발생할 수 있다. 임시 수신·검증·완료 구분과 정리 절차를 2·10번에서 함께 검토한다. 저장 용량이 부족하면 대기 자료를 조용히 버리는 대신 상태를 알리고 새 수집·보존 정책을 적용한다. 구체적인 용량·보존 기간은 팀이 정한다.
