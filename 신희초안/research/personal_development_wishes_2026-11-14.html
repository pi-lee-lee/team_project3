첫 계산의 구체적인 예시

제안한 예시는 시간표시가 있는 센서 수신 기록을 읽어 인접 기록 사이의 간격을 계산하는 기능입니다. 간격의 분포와 사전에 정한 기준을 넘긴 구간을 CSV로 저장하고, Matplotlib으로 그래프를 만듭니다. 사용자는 특정 작업에서 관측이 끊긴 구간과 관련 로그를 함께 조사할 수 있습니다.

필요한 입력은 작업 ID, 센서 구분, 수신 시각, 시각의 단위·기준입니다. 재시작 구간을 구분하고, 정렬·중복·누락값 처리 기준을 기록합니다. 간격 계산과 구간 추출이 실제 분석이며, Matplotlib은 계산 결과를 시각화합니다. 수신 간격만으로 센서 고장 원인을 확정할 수 있는 범위는 제한됩니다.

완료 시험은 간격을 알고 있는 고정 시험 파일로 계산 결과를 대조한 뒤, 서버 연결을 끊고 앱을 재실행해 같은 결과를 여는 것입니다. 이후 실장비 자료를 별도로 시험합니다. 카메라 쪽을 먼저 검증하려면 OpenCV로 지정 ROI의 밝기·어두운 영역 비율을 계산하고 촬영 조건별로 비교하는 방법도 후보입니다. 첫 분석 종류는 선택 전입니다.

2순위로 유지할 기능

로봇 상태·로그·그래프·진단은 로컬 조사 작업을 돕는 기능으로 유지합니다. 기존 6번 작업 시간축 조사, 7번 자료 묶음 내보내기, 8번 기록 자료 반복 시험, 15번 주행·센서 기록 비교 등이 연결됩니다. 실시간 표시·일반 그래프·재생은 웹 및 Foxglove와의 중복을 확인하고, 반복 분석·설정 비교·결과 보존에서 추가 가치를 검토합니다.

한 건의 작업이 세 프로그램을 거치는 모습

  • ① 요청과 기록 — 관리자가 점검 대상 한 곳을 선택합니다. 백엔드는 작업 ID와 요청 내용을 저장하고 실행 측에 전달합니다.
  • ③ 수행과 관측 — 실행 프로그램이 이동·촬영을 수행하고, 사진·실행 이벤트·지원되는 상태값을 수집합니다. 서버가 자료 수신을 확인한 뒤 사용자에게 결과를 제공합니다.
  • ② 가져오기와 계산 — 담당자가 해당 작업 자료를 로컬 폴더로 가져옵니다. 서버 연결 없이 로그와 센서 간격을 분석하고 결과 CSV·그래프·설정을 저장합니다.
  • ② 재열기와 외부 도구 활용 — 앱을 다시 열어 결과를 확인하거나 CSV를 스프레드시트로 조사합니다. 새 결과물에는 원래 작업·입력 파일·분석 실행의 연결을 남깁니다.
  • ② → ① 결과 제출 — 연결이 복구되면 담당자가 선택한 분석 결과와 의견을 제출합니다. 백엔드는 제출 버전과 근거를 기록하고, 공식 확인 상태의 변경은 별도 검토 절차에 따릅니다.

로봇 → 서버의 결과 보관·복구 전송은 기존 10번, 서버 → PC 자료 가져오기는 25번, PC → 서버 분석 제출은 26번입니다. 각 전송은 해당 작업의 책임 영역에서 구현하고 공통 식별자를 사용합니다.

업무 상태와 실행 사실을 연결하는 기준

백엔드는 요청·취소 의사와 공식 업무 기록을 관리하고, 실행 측은 실제로 시도한 동작과 관측 결과를 기록합니다. 재접속 시 작업 ID·실행 시도 ID·이벤트 순서를 대조합니다. 취소 요청 접수와 로봇의 취소 완료는 각각 확인합니다. 재시작 뒤 물리 동작의 결과가 불명확하면 확인 절차를 거치며, ID 기반 중복 제거에 더해 이러한 불명 상태를 다루어야 합니다.

주기적으로 얻는 배터리·센서·구동 관련 값은 설치 환경에서 지원 여부·단위·갱신 주기를 확인한 뒤 활용합니다. 제공되지 않는 값과 오래된 값을 표시하고, 상태 조회·활용에 해당하는 개발 성과로 설명합니다. 두 로봇의 임무와 같은 상태 데이터 제공 여부는 실제 확인 후 결정합니다.
